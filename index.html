Recursive Cognition Cycle
A non‑linear loop for how an agent observes, interprets, updates itself, and acts—then re‑enters the cycle with new state.
Non‑linear · Recursive · Adaptive Model: RCC Author: Dakota
Concept overview
RCC core
Non‑linear state transitions

The Recursive Cognition Cycle (RCC) is a loop where an agent repeatedly: samples reality, evaluates it against internal models, updates those models, and chooses actions. The cycle is non‑linear: any phase can trigger a jump to another phase or a full reset, depending on context, uncertainty, or new information.

  • Stateful: each pass through the cycle mutates the agent’s internal state.
  • Recursive: outputs of one cycle become inputs to the next.
  • Context‑driven: transitions are governed by rules, thresholds, or heuristics.
Cycle phases
Phase definitions
1 · Perception
⇢
Raw input from environment, memory, or other agents. Noise, ambiguity, and gaps are preserved—not magically cleaned.
2 · Interpretation
⇢
Map inputs onto existing beliefs, schemas, and narratives. Detect conflicts, anomalies, and pattern breaks.
3 · Self‑update
⇢
Adjust internal models: beliefs, priorities, risk estimates, identity stories. This is where the agent actually changes.
4 · Action
⇢
Choose and execute behavior in the world or internally (e.g., deciding not to act is still an action).

In a strictly linear system, the cycle would always be Perception → Interpretation → Self‑update → Action → Perception. RCC relaxes that constraint and allows jumps, loops, and short‑circuits.

Non‑linear transitions
Graph logic
Short‑circuits & feedback spikes

Instead of a single fixed loop, RCC is a directed graph of possible transitions. Edges are activated by conditions like uncertainty, emotional load, or external constraints.

  • Perception → Action: reflexive behavior without deep interpretation.
  • Interpretation → Interpretation: rumination or re‑framing loops.
  • Action → Self‑update: identity shifts driven by what the agent just did.
  • Self‑update → Perception: seeing the same world differently after a belief change.

The “cycle” is therefore not a circle but a dynamic network that the agent traverses over time, recursively folding new outcomes back into future passes.

RCC as a system
Implementation lens

You can treat RCC as an architecture pattern for agents, algorithms, or workflows:

  1. Define state: what the agent “is” at any moment (beliefs, goals, memory).
  2. Define phases: perception, interpretation, self‑update, action.
  3. Define edges: rules that decide which phase comes next.
  4. Run recursively: each completed pass feeds the next as updated state.

This page is intentionally abstract so you can plug RCC into code, behavior models, or personal reflection without changing the core idea.

Example traversal
Narrative trace
Step A · Perception
Agent receives conflicting feedback: “You’re doing great” and “You missed the mark.”
Step B · Interpretation → Interpretation
Agent loops, trying different narratives: “I’m improving” vs “I’m failing.” The loop continues until uncertainty drops below a threshold.
Step C · Self‑update
Agent updates its model: “I’m capable but inconsistent; I need structure.” This becomes part of its identity and future expectations.
Step D · Action → Self‑update
Agent designs a new routine. Acting on it reinforces the updated identity, feeding back into the next cycle’s starting state.
